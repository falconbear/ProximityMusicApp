# ui-design-quality — UI プロジェクトのデザイン品質レーン

UI (Web / モバイルアプリ) を持つプロジェクトで、skeptical-evaluation の合否スコアとは**別レーン**の補助評価を提供する。

## 位置付け

- 合否判定には使わない。PASSED / NEEDS_FIX は skeptical-evaluation の 5 基準のみで決まる
- スコアと指摘は `docs/feedback/issue-<id>.md` の `## Design Quality (advisory)` セクションに記録
- 例外: 4 軸のいずれかが **2 以下 (破綻レベル)** の場合は、品質基準 (UX/可読性) を 3 未満として扱い、合否に反映させる

## 4 軸評価 (1-10 スケール、重み付け)

| 軸 | 重み | 説明 |
|---|---|---|
| **Design Quality** | 0.3 | コヒーレントな全体感。プロフェッショナルなデザイナーの作と見紛うか |
| **Originality** | 0.2 | テンプレ/AI パターンと一線を画す創造的判断があるか |
| **Craft** | 0.3 | タイポグラフィ・スペーシング・アニメーション・マイクロインタラクション |
| **Functionality** | 0.2 | 全機能が実際に動くか (合否側の契約ベーステストと重複、参考値) |

**総合スコア** = Σ(軸スコア × 重み)。8.0+ がプロ品質、6.0-7.9 が実用水準、6.0 未満は改善推奨。

## 1-10 帯域の定義 (アンカー)

各軸の数値を同じ意味で扱うためのアンカー表。

| スコア | 意味 |
|---|---|
| **1-3** | 壊れている / 誰にも見せられない / "AI slop" の極み |
| **4-5** | 機能するが明らかに AI 生成、チュートリアル品質 |
| **6** | 普通だが地味、仕上げが欠落 |
| **7** | 良い — ジュニア開発者の堅実な成果 |
| **8** | かなり良い — プロ品質だが粗が残る |
| **9** | 優秀 — シニア品質、磨き抜かれている |
| **10** | 卓越 — 製品としてそのまま出荷可能 |

評価者全員がこの表を同じ意味で使う前提。「7 点」と書かれたら「ジュニア堅実」の意味に統一。

## First Impression (30 秒テスト)

評価開始の最初の 30 秒で以下を観察し、第一印象を `## Design Quality (advisory)` に記録する:

- エラーなくロードされるか
- 即座の視覚的印象 (プロダクト / チュートリアルプロジェクト)
- 視覚的階層が明確か
- 「これはダメだ」と感じたら、それは正しい直感 — 後で言語化する

## AI Slop 回避カタログ (減点対象)

以下のパターンは「AI 生成感の強い定型」として **Originality と Craft を減点**する根拠になる。

### 視覚的アンチパターン

- **汎用グラデーション背景** (例: `#667eea → #764ba2`。これが見えたら一発で AI 生成が疑われる)
- **すべての要素に過剰な rounded corners**
- **ストック Hero セクション** (「Welcome to [App Name]」風の定型)
- **カスタマイズなしの Material UI / Shadcn / Tailwind UI デフォルトテーマ**
- **Unsplash / placeholder.com のプレースホルダ画像**
- **同一レイアウトの汎用カードグリッド**
- **装飾目的の AI 生成風 SVG パターン**

### 機能的アンチパターン

- **"Something went wrong" だけのエラーページ** (ユーザーに行動指針を示さない)
- **Loading スピナーが無く、瞬間的にレンダされる** (非同期感がない → fake データ疑惑)
- **ホバー / フォーカス / アクティブ状態の欠如** (CSS 未調整)
- **Empty state が無い** (0 件時に「データなし」だけ)

### 目指すべき方向 (高スコアの判断基準)

- 具体的で意見のあるカラーパレット (プロジェクト CLAUDE.md で指定されているか)
- 思慮深いタイポグラフィ階層 (weight / size の使い分け)
- コンテンツに合ったカスタムレイアウト (汎用グリッドを避ける)
- ユーザーアクションに結びついた意味のあるアニメーション (装飾ではない)
- 人格のある empty state
- ユーザーを助けるエラー状態 (次の行動を示す)

## ワークフロー (opt-in evaluator 向け)

skeptical-evaluation のワークフローに以下を追加:

1. **First Impression (30s)**: 初期印象をメモ
2. **4 軸採点**: 各軸を 1-10 で採点し、根拠を 1-2 文で記述
3. **AI Slop カタログと照合**: 該当パターンがあれば具体例を引用
4. **総合スコア算出**: 重み付け平均
5. **Feedback に記録**: `docs/feedback/issue-<id>.md` の `## Design Quality (advisory)` セクション

雛形:

```markdown
## Design Quality (advisory, not affecting pass/fail)

**First Impression (30s)**: <印象>

| 軸 | Score | 根拠 |
|---|---|---|
| Design Quality | X/10 | ... |
| Originality | X/10 | ... |
| Craft | X/10 | ... |
| Functionality | X/10 | ... |

**総合スコア**: X.X / 10

**AI Slop 該当**:
- <該当パターンと該当箇所>

**改善方向 (advisory)**:
- <具体的な改善提案>
```

## 禁止事項

- **合否判定に使用しない** (例外: 軸スコア 2 以下の破綻ケースのみ)
- **主観的な好みで減点しない** (必ず AI Slop カタログや 1-10 アンカーに照らして根拠を示す)
- **契約に無い要素を要求しない** (例: 契約で「ダッシュボードを作る」とあるのに、「アニメーションが無い」で減点するのは越権)
