## Issue 分割の指針 (planner 内部メモ)

- 1 Issue = 1 機能 (または 1 機能の 1 層) を目安に。
- 機能が大きければ「実装」「テスト」「migration」など段階で割る。
- 各 Issue は GitHub Issue として登録し、`bin/controller.py init` で `.ai/work/<id>/` を作る。
- Issue body には Goal / Scope / Out of scope / Acceptance criteria / Priority / Risk / Dependencies + spec.md の該当アンカー。
