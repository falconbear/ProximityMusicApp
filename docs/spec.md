## 概要

ProximityMusicApp は、すれ違った周囲端末から自動で短尺楽曲を受け取り、即時再生で
偶発的な音楽との出会いを生み出す iOS / Android 向け Flutter モバイルアプリ。
パーソナライズに疲れたユーザーに「他人の playlist が偶然耳に入る」体験を、サーバ非依存の
P2P で提供する。MVP では実機 2 種で「すれ違い検知 → セッション確立 → サンプル楽曲受信 →
即時再生」が完走することを最小成立条件とする。

## ターゲットユーザー

- 音楽好きで、自分のレコメンド枠の外側にある楽曲との偶然の出会いを楽しみたい人
- イベント / カフェ / 通勤など、人が集まる場所での副次体験として音楽を取り入れたい人
- プライバシーを重視し、サーバに音楽嗜好を預けたくない人

## デザイン方針 (UI/UX)

既存実装のダークテーマを継承する。**汎用的な AI-slop UI を避ける**ため以下を厳守:

- **カラーパレット (固定)**:
  - Primary: `#1DB954` (Spotify-like green、既存資産)
  - Background: `#121212` / Surface: `#181818` / Elevated surface: `#222222`
  - Text primary: `#FFFFFF` / Secondary: `#B3B3B3`
  - Accent (近接イベント強調): `#FF6B6B` (受信通知やコネクションパルス用)
- **タイポグラフィ階層**: 画面タイトル (24/Bold) / セクション (18/Semibold) / 本文 (14/Regular) /
  メタ情報 (12/Regular)。フォントは OS 標準を使用し、可読性を犠牲にしない
- **レイアウト思想**: 「単一の楽曲をフルスクリーンで没入させる」既存プレイヤー UI を主軸に、
  検知・受信履歴は **ボトムシート / モーダル** で重ね、再生体験を遮らない
- **モーション**: 近接検知中の「波紋アニメーション」、受信成立時の「ピアアバターからプレイヤーに
  楽曲が滑り込む」遷移など、機能性を伝えるアニメーションのみ採用 (装飾的アニメ禁止)
- **アバター表現**: 各ピアに匿名の **幾何学的識別アイコン** を割り当て (色 + 形状の組合せ)。
  実名 / 写真は扱わない

### AI-Slop アンチディレクティブ (evaluator 減点対象)

- 禁止: 汎用的な紫青グラデーション (`#667eea → #764ba2` 等)、ストック画像、
  Material UI そのままのデフォルト、Unsplash プレースホルダー、汎用カードグリッド
- 必須: 各画面の **空状態 / エラー状態 / ロード状態** を明示的に設計
- 必須: 各画面で「権限拒否 / Bluetooth OFF / 圏外 / ストレージ満杯」のリカバリ動線
- 必須: ピアごとの匿名アイコンに人格を持たせ、空のリストでも寂しくない empty state

## 機能詳細

### 1. プロジェクト基盤整備

**ゴール:** 後続 Issue の generator / evaluator が冪等に起動・テスト可能な土台を作る。
既存の単一ファイル実装 (`lib/main.dart`) を Presentation / Domain / Data の 3 層に
最小分割し、後続機能の追加余地を確保する。

**ユーザーから見える振る舞い:**
- (このスプリントで UI は変わらない)
- 既存の楽曲再生 / ミニプレイヤー / ダーク UI は **回帰せず動作する**

**Out of scope:**
- 新機能の追加 (近接検知 / 転送 / セキュリティ等は別 Issue)
- 完全なクリーンアーキテクチャ準拠 (最小分割で可、過剰設計しない)
- ネイティブ実装 (Platform Channels の追加は近接検知 Issue で行う)

**受け入れ基準:**
- リポジトリルートに `init.sh` が存在し、`./init.sh` を 2 回連続で実行しても壊れない (冪等)
- `./init.sh` が Flutter SDK の存在チェック → `flutter pub get` → テスト実行コマンドの提示まで通る
- `flutter analyze` がエラーなしで通る
- `flutter test` で **既存 widget smoke test を含む全テストが green**
- `lib/` 配下に最低限の層分離 (例: `presentation/` `domain/` `data/`) が存在し、
  既存の楽曲再生 / プレイヤー UI 機能が同等に動作する (機能回帰なし)
- GitHub Actions ワークフローが存在し、push 時に format / analyze / test を自動実行する
- README に `./init.sh` での起動手順とテスト方法が記載されている

### 2. オンボーディングと権限取得

**ゴール:** ユーザーが本機能の前提 (近接通信、バッテリ影響、権利クリア音源のみ扱う) を理解した上で
OS 権限を付与し、メイン画面に到達できるようにする。

**ユーザーから見える振る舞い:**
- 初回起動時にウェルカム画面 → プライバシー / 電池影響説明 → 必要権限の説明 → 権限ダイアログ誘導
- 必要権限: Bluetooth / 近接通信、バックグラウンド再生、通知 (iOS / Android で適切なもの)
- 権限拒否時は「機能制限モード」で再生のみ続行可能、設定画面から後で付与できる導線を表示
- 2 回目以降の起動ではオンボーディングをスキップしてメイン画面に直行

**Out of scope:**
- 利用規約 / 同意ボタンのバージョン管理 (機能 13 で扱う)
- アクセシビリティ最適化 (MVP 後)

**受け入れ基準:**
- 初回起動時、ウェルカム / プライバシー説明 / 権限要求の **3 ステップ以上のスクリーン** が順に表示される
- 各ステップで「次へ」「戻る」「スキップ」のいずれかのナビゲーションが提供されている
- ユーザーが Bluetooth 権限を許可するとオンボーディング完了状態が永続化され、
  アプリ再起動時にメイン画面に直行する
- ユーザーが Bluetooth 権限を拒否した場合、メイン画面には「近接機能は無効です。
  設定から有効化できます」というバナーが恒常表示される
- 権限拒否状態で楽曲再生 (既存機能) は引き続き利用可能である
- 設定画面から「権限を再要求」が押下できる

### 3. 近接検知 (Discovery)

**ゴール:** 周囲端末を匿名で検知し、リアルタイムに検知済みピアの一覧を提示する。
ユーザーは「今、近くに何台いるか」を視覚的に把握できる。

**ユーザーから見える振る舞い:**
- メイン画面に「Discover」ビュー (波紋アニメーションを伴うレーダー風表示) が存在する
- 検知トグル (ON/OFF) があり、ON の間だけスキャンを行う
- 検知された各ピアは **匿名の幾何学的アイコン** で表示され、
  最終検知時刻 (相対表記、例: 「5 秒前」) とともにリスト化される
- 同一ピアが複数回検知されても重複表示しない (匿名 ID 単位で集約)
- 一定時間 (既定 60 秒) 検知されないピアは自動的にリストから消える
- 検知 0 件の状態では「周囲に誰もいません。場所を変えてみてください」という空状態を表示
- 検知中は画面下部に「N 台検知中」のサマリが常時表示される

**Out of scope:**
- ピアとのセッション確立や楽曲転送 (機能 4 / 5 で扱う)
- ピアのプロファイル詳細表示 (匿名性維持のため意図的に最小)
- 位置情報の利用 (Bluetooth / 近接通信のみで完結させる)

**受け入れ基準:**
- 検知トグルを ON にすると、5 秒以内にスキャンが開始される (UI 上のスキャン中インジケータで確認可能)
- 別端末でアプリを起動した状態で 1m 以内に置くと、30 秒以内に Discover ビューに該当ピアが現れる
- 検知トグルを OFF にすると、即座にスキャンが停止し、リストはフリーズする
   (新しい検知が追加されない)
- Bluetooth が OFF の状態で検知トグルを ON にすると、
   「Bluetooth が無効です。設定を確認してください」というエラー UI が表示される
- 同一ピアが連続して検知されても、UI 上は 1 件として表示され、最終検知時刻が更新される
- 60 秒間再検知されないピアは自動でリストから消える

### 4. 匿名セッション確立

**ゴール:** 検知済みピアと一時的に安全なセッションを確立し、楽曲交換の前提条件を整える。
**匿名 ID は周期的にローテーション** され、長期追跡を不可能にする。

**ユーザーから見える振る舞い:**
- ピアアイコンをタップするか自動マッチング条件 (両者がトグル ON) を満たすと、
  バックグラウンドでセッション確立が試行される
- セッション確立中はピアアイコンに「接続中」インジケータが表示される
- 確立成功時はアイコンが「接続済み」状態になり、楽曲受信待機に入る
- セッション失敗時はエラー状態になり、再試行ボタンが表示される
- 自分の匿名 ID は毎回起動時、および一定時間 (既定 15 分) ごとに自動でローテーションする
- ユーザーは設定画面から「自分の匿名 ID を今すぐ更新」を実行できる

**Out of scope:**
- 実際の楽曲転送 (機能 5 で扱う)
- ピアの認証 / アカウント概念の導入 (匿名性維持のため永続的な識別子は持たない)
- バックエンドサーバ経由のセッション仲介 (P2P 完結)

**受け入れ基準:**
- 検知済みピアをタップすると、10 秒以内にセッション確立成功または失敗が UI に反映される
- セッション確立中にユーザーが画面遷移しても、確立処理は中断されない
- セッション確立成功時、ピアアイコンに「接続済み」表示が出て、楽曲受信を受け付ける状態になる
- 自分の匿名 ID は **アプリ起動毎と 15 分間隔のいずれか早い方** でローテーションする
- ローテーション後、過去の匿名 ID で確立済みのセッションは自動切断される
- 設定画面の「匿名 ID を今すぐ更新」を実行すると、即時にローテーションが行われ、
  画面に新 ID のフィンガープリント (短縮形) が表示される

### 5. P2P 楽曲転送

**ゴール:** 確立済みセッション越しに、短尺楽曲を **チャンク単位で受信し、整合性検証 + 暗号化**
を行ったうえでローカルに保存する。

**ユーザーから見える振る舞い:**
- 接続済みピアから楽曲が送られてくると、画面に「<曲名> を受信中…」とプログレスが表示される
- 転送進捗 (パーセンテージ) がリアルタイムで更新される
- 整合性検証に失敗した楽曲は **自動破棄** され、ユーザーには「受信失敗」のトーストが出る
- 受信成功時、機能 6 (即時再生 / キュー追加) にバトンを渡す
- 同時に複数ピアから受信が来た場合、**最初の 1 件を採用し** 後続は次のキュー候補にフォールバック
- 転送中にピアが圏外になった場合、即時に「転送中断」になりキューが進む

**Out of scope:**
- 楽曲送信側の操作 UI (MVP では受信側体験を優先する。送信ロジック自体は両方向動作するが
  送信曲の選択 UI は最小限とする)
- リトライ (失敗時は破棄し、次のすれ違いに賭ける)
- 大容量楽曲 (フルレングス) への対応 — 短尺サンプル (例: 30 秒〜90 秒程度) のみ

**受け入れ基準:**
- 受信中、画面に楽曲名 / アーティスト / 進捗 % がリアルタイム (1 秒以内更新) で表示される
- 整合性検証 (ハッシュ等) に失敗した受信は破棄され、ローカルに保存されない
- 転送中にピアが切断された場合、UI に「転送中断」が表示され、ユーザー操作なしで次の状態に進む
- 受信成功した楽曲はローカルストレージに **暗号化された状態で** 保存される
- ストレージ上限 (機能 9) を超える受信は、最古の非お気に入り楽曲が自動削除されてから保存される
- 同一楽曲を異なるピアから受信した場合、重複保存しない (内容ハッシュで判定)

---

### 6. 受信即時再生 + 自動再生キュー

**ゴール:** 受信完了した楽曲を即座に再生し、後続受信を自動でキューイングして連続再生する。
ユーザーは何も操作しなくても「次から次へと知らない曲が流れる」体験を得る。

**ユーザーから見える振る舞い:**
- 楽曲受信完了の瞬間、再生中の曲が無ければ **即時に再生開始**
- 再生中に新規受信があれば、**現在の曲の後ろにキューイング**
- ミニプレイヤー / フルプレイヤー (既存資産を継承) で次曲・前曲・スキップ・お気に入りが可能
- 「スキップ」を押すとキュー内の次曲に即座に進む
- キューが空になったら再生は自動停止し、Discover ビューに戻る (またはミニプレイヤーが消える)
- お気に入り済み楽曲は **キューが空でも再生終了せず**、お気に入りからシャッフル再生に切り替わる
  (フォールバック挙動、設定で OFF 可能)

**Out of scope:**
- レコメンド / ランキング
- プレイリストの手動編集 (キューは受信順 + シャッフル限定)
- クロスフェード / イコライザ等の高度な再生機能

**受け入れ基準:**
- 楽曲を受信完了した瞬間 (再生中の曲が無い状態) から、**2 秒以内に再生が開始**される
- 再生中に新規受信が完了した場合、現在の曲の再生が中断されず、
  キューに追加されたことが UI で確認できる
- スキップボタンを押すと **1 秒以内に次の楽曲の再生が開始**される
- キューが空かつお気に入り 0 件の状態では、再生終了後にミニプレイヤーが消え、
  Discover ビューが前面に来る
- バックグラウンドでも上記の自動再生・キューイングが継続する (機能 7 と連動)

---

### 7. バックグラウンド受信・再生

**ゴール:** アプリを閉じた / バックグラウンドに送った状態でも、近接検知・受信・再生が
**OS のガイドライン範囲内で** 継続する。

**ユーザーから見える振る舞い:**
- アプリをバックグラウンドにしても、検知トグルが ON の限り検知が継続する
   (OS 制約により頻度は低下する場合がある)
- バックグラウンドで楽曲を受信した場合、ロック画面 / 通知センターのメディアコントロールに
  楽曲情報が表示される
- ロック画面 / 通知から再生・一時停止・スキップが可能 (既存資産を継承)
- アプリを完全終了した場合は検知が停止する (ユーザーに事前に明示)
- バッテリ消費を抑えるため、バックグラウンドではスキャン頻度を間引く

**Out of scope:**
- iOS の長時間バックグラウンド実行回避策 (脱獄相当の手法)
- アプリ完全終了状態でも検知を継続する仕組み (将来 Issue で push 通知連携を検討)

**受け入れ基準:**
- アプリをバックグラウンドにした後 1 分以内に楽曲を受信すると、
  メディア通知 (ロック画面) に該当楽曲が表示される
- ロック画面の「再生」「一時停止」「次へ」が **既存プレイヤーと同じ挙動** で動作する
- バックグラウンドでスキャン頻度がフォアグラウンドより低下することを **計測値で確認** できる
  (例: 1 分間のスキャン回数を比較)
- アプリ完全終了 (タスクキル) 状態では検知が停止し、再起動するまで再開しない
- バックグラウンド遷移時に「バックグラウンドでも受信を続けます」という通知が **初回のみ** 表示される

### 8. フィルタリング (ブロック / お気に入り / スキップ)

**ゴール:** ユーザーが受信内容を制御できるようにし、不快な体験を避けつつ、好みの楽曲を蓄積できる。

**ユーザーから見える振る舞い:**
- 再生中の楽曲に対して **「お気に入り」** ボタンが押せる (既存 UI を継承)
- 再生中の楽曲に対して **「スキップ」** ボタンで次曲に進める
- 再生中の楽曲の送り元ピアを **「ブロック」** できる (確認ダイアログあり)
- ブロックされたピアからの **以降の受信は自動拒否** され、UI には何も表示しない
- ブロックリストは設定画面から確認・解除できる (匿名 ID のフィンガープリントで列挙)
- お気に入り済み楽曲は受信ライブラリで「お気に入り」フィルタで一覧可能 (機能 9 と連動)
- スキップした楽曲は**再生履歴上「スキップ」とマークされ**、自動再生から除外される

**Out of scope:**
- 楽曲単位のブロック (送り元ピア単位のみ)
- ソーシャル機能 (フォロー等)
- 共有プレイリスト

**受け入れ基準:**
- お気に入りボタンを押すと、押下後 1 秒以内に UI が反映され、ライブラリ (機能 9) に登録される
- スキップボタンを押した楽曲は、その曲のメタデータに「スキップ」フラグが立ち、
  自動再生キューには再追加されない
- ピアをブロックすると、確認ダイアログ後に即時ブロックリストに登録される
- ブロック後、同一ピアから新たな受信があっても **UI には何も表示されず、ローカル保存もされない**
- 設定画面のブロックリストから解除すると、解除後の受信は通常通り処理される
- ブロック解除後の挙動が「次回検知から有効になる」「すでに切断済みのセッションは復元しない」
  であることが UI に明記されている

### 9. 受信楽曲ライブラリ

**ゴール:** ユーザーが過去に受信した楽曲を確認・管理し、ストレージ上限を超えないように
自動でクリーンアップする。

**ユーザーから見える振る舞い:**
- 「ライブラリ」タブに、受信履歴一覧が新しい順で並ぶ
- 各エントリは「楽曲名 / アーティスト / 受信日時 / 送信ピアの匿名アイコン」を表示
- フィルタとして「すべて / お気に入り / 最近 24 時間」が選択可能
- エントリをタップすると即時再生される
- ライブラリ画面下部に「使用中ストレージ X MB / 上限 Y MB」のバーが表示される
- ストレージ上限に達した場合、新規受信時に **古い非お気に入り楽曲から自動削除** される
- ユーザーは個別エントリを長押しで手動削除できる
- 設定画面から「ライブラリを全消去」が実行できる (確認ダイアログあり、お気に入りも消える)

**Out of scope:**
- 楽曲のエクスポート / 共有 (権利上の懸念)
- クラウドバックアップ
- 詳細なメタデータ編集

**受け入れ基準:**
- 受信した楽曲は受信完了から 2 秒以内にライブラリ一覧に表示される
- 「お気に入り」フィルタを選ぶと、お気に入り済みのエントリのみ表示される
- ストレージ使用量バーが、実際のローカル使用量と整合 (誤差 ±5%)
- ストレージ上限 (既定 200 MB、設定で変更可) を超える受信があると、
  最古の非お気に入り楽曲が削除されてから新規楽曲が保存される
- お気に入り済みの楽曲はストレージ上限超過時にも **自動削除されない**
- 「ライブラリを全消去」を実行すると、確認ダイアログを経たうえで全楽曲 (お気に入り含む) が削除され、
  ストレージ使用量が 0 になる

### 10. 電池消費とスキャン制御

**ゴール:** 「常時 ON で 1 時間放置しても電池が異常消費しない」ことをユーザー側でコントロール可能にする。

**ユーザーから見える振る舞い:**
- 設定画面に「省電力モード」トグルがあり、ON の間はスキャン頻度が大幅に低下する
- メイン画面の「検知トグル」自体に加え、自動停止オプション (例: 「30 分後に自動 OFF」「電池 20%
  以下で自動 OFF」) を選べる
- 検知中は画面下部に「推定 1 時間あたりの電池消費: 約 X%」の指標が表示される
  (設定画面で OFF 可)
- 低電力モード (OS 側) を検出した場合、自動でスキャン頻度を低下させる
- バックグラウンドでは常時、フォアグラウンドより低い頻度でスキャンする (機能 7 と整合)

**Out of scope:**
- 厳密なバッテリプロファイリング (実機計測は別タスク)
- 端末別チューニング (汎用設定で良しとする)

**受け入れ基準:**
- 「省電力モード」を ON にすると、スキャン間隔が **設定値に応じて 2 倍以上** に伸びる
   (内部メトリクスで確認可能)
- 「30 分後に自動 OFF」を設定して 30 分経過すると、検知トグルが自動 OFF になり、
  ユーザーに通知される
- 「電池 20% 以下で自動 OFF」を設定して残量が 20% を下回ると、検知トグルが自動 OFF になる
- OS 低電力モードが ON の状態で検知トグルを ON にすると、
  「低電力モードのためスキャン頻度を抑えています」というバナーが表示される
- 「推定電池消費」指標は **直近 10 分間のスキャン頻度に基づき、毎分更新** される

### 11. ログ / メトリクス / 障害対応

**ゴール:** 運用上必要最小限のメトリクスとクラッシュ情報を取得し、デバッグと改善のサイクルを回せる
土台を作る。

**ユーザーから見える振る舞い:**
- (本機能は主に裏側) ユーザー UI には影響しないが、設定画面の「データ収集について」から
  どんな情報を取得しているかを確認できる
- ユーザーは設定画面から **メトリクス収集を OFF** にできる (デフォルト ON、説明文付き)
- アプリがクラッシュした次回起動時、「先回エラーが発生しました。レポートを送信しますか?」
  という同意ダイアログが表示される (送信先はローカルログファイル、サーバ送信は MVP では行わない)

**Out of scope:**
- リモートメトリクスサーバへの送信 (P2P 前提のため、MVP では端末内ログのみ)
- リアルタイムダッシュボード

**受け入れ基準:**
- 端末内ログに以下のイベントが記録される:
  すれ違い検知 / セッション確立成否 / 転送成否 / 再生イベント / ブロック / クラッシュ
- 設定画面の「ログを書き出す」を実行すると、ローカルファイルとして共有 / 保存できる
- メトリクス収集を OFF にすると、以降のイベントが記録されない
- クラッシュ後の起動時、ユーザーが「送信しない」を選べばローカルにのみ保持される
- ログには **個人識別情報 (匿名 ID 以外の永続 ID、位置情報、楽曲メタデータの詳細) が含まれない**

### 12. 設定画面

**ゴール:** ユーザーが本アプリの挙動を一箇所で確認・調整できる中央コンソールを提供する。

**ユーザーから見える振る舞い:**
- 「設定」タブから以下のセクションにアクセスできる:
  - **検知**: 検知トグル / 省電力モード / 自動 OFF / 匿名 ID 即時更新
  - **ストレージ**: 上限変更 / 使用量表示 / 全消去
  - **プライバシー**: ブロックリスト管理 / メトリクス OFF / ログ書き出し
  - **権限**: OS 権限の状態と再要求リンク
  - **アプリ情報**: バージョン / 利用規約 / プライバシーポリシー
- 各設定変更は即時反映され、明示的な「保存」ボタンは不要

**Out of scope:**
- 通知の細かいカスタマイズ (MVP 後)
- テーマ切り替え (ダーク固定で良い)

**受け入れ基準:**
- すべての設定変更が **押下後 1 秒以内** に反映される
- 設定値はアプリ再起動後も永続化されている
- 「全消去」「ブロック解除」「ID 即時更新」など破壊的操作には確認ダイアログがある
- 各セクションが視覚的に区切られ、スクロールで全項目にアクセス可能

### 13. 利用規約 / プライバシー同意フロー

**ゴール:** 本アプリの前提 (権利クリア音源のみ扱う / データ取扱) をユーザーに明示し、明示的な同意を得る。

**ユーザーから見える振る舞い:**
- 初回オンボーディング (機能 2) の中で、利用規約 / プライバシーポリシーへの **同意チェック**
  がある (チェックしないと先に進めない)
- 設定画面からいつでも規約 / ポリシー本文を閲覧可能
- 規約バージョンが更新された場合、次回起動時に **再同意フロー** が表示される

**Out of scope:**
- 法務的な精査 (法務担当のレビュー)
- 多言語対応 (MVP 後)

**受け入れ基準:**
- 初回起動時、利用規約とプライバシーポリシーへの同意チェックが必須となり、
  未チェックでは「同意して続行」ボタンが活性化しない
- 規約本文は **アプリ内で全文が閲覧可能** で、外部ブラウザに飛ばさなくても読める
- 同意したバージョン番号 (例: `v1`) が永続化される
- 規約バージョンを更新したビルドを起動すると、再同意フローが表示される
- ユーザーが再同意を拒否した場合、アプリは検知 / 受信 / 再生機能を停止し、
  利用規約画面と「同意する」「アプリを終了」のみ操作可能になる

## UI/UX 要件

### 画面構成 (タブベース)

1. **Discover** (中央) — 近接検知ビュー、検知済みピア一覧、検知トグル
2. **Player** (上部に常駐 / 中央タップでフル) — 既存ミニプレイヤー / フルプレイヤー
3. **Library** (左) — 受信楽曲履歴 / お気に入り
4. **Settings** (右) — 機能 12 のすべて

### 主要遷移

- 起動 → (初回のみ) オンボーディング → Discover
- Discover → ピアタップ → セッション確立中表示 → 接続済みアイコンに変化
- 楽曲受信 → ミニプレイヤー出現 → タップでフルプレイヤー
- フルプレイヤー → 戻るで元タブに戻る
- 設定 → ブロックリスト → 個別解除画面

### 状態表示の必須項目 (各画面共通)

- **空状態 (Empty)**: 「検知 0 件」「ライブラリ 0 件」など、それぞれに固有のコピーとアイコン
- **エラー状態 (Error)**: Bluetooth OFF / 権限拒否 / ストレージ満杯のリカバリ動線付き
- **ロード状態 (Loading)**: スケルトン UI またはスピナー
- **オフライン状態**: P2P 中心なので「オンライン必須」ではないが、OS 機能で制限がある場合は明示

## 非機能要件

### パフォーマンス
- 検知トグル ON → スキャン開始: **5 秒以内**
- 受信完了 → 再生開始: **2 秒以内**
- スキップボタン → 次曲再生: **1 秒以内**
- 設定変更 → 反映: **1 秒以内**
- アプリ起動 (cold) → メイン画面表示: **3 秒以内** (初回オンボーディング除く)

### バッテリ
- 検知 ON 状態で **1 時間あたり電池消費 5% 以内** を目標 (要実機検証)
- 省電力モードでは消費がさらに半減

### セキュリティ / プライバシー
- 匿名 ID は **15 分以内に必ずローテーション**
- 楽曲データは転送時 / 保存時とも **暗号化**
- 永続的な個人識別子 (端末 ID / アカウント等) は持たない
- 位置情報を取得しない

### 対応 OS
- iOS 15 以降
- Android 10 (API 29) 以降

### テスト
- ユニットテスト: Domain / UseCase 層をカバー
- ウィジェットテスト: 主要画面の状態遷移
- インテグレーションテスト: 転送フェイクを使った受信→再生フロー
- E2E (実機): MVP 受け入れ基準の通し確認 (手動 OK)

## 制約事項

### Out of scope (MVP)
- レコメンド / ランキング / ソーシャル機能
- DRM / 配信権管理 (権利クリア音源のみ扱う前提)
- バックエンドサーバ運用 (P2P 完結、必要になれば後続スプリントで GCP サーバレス検討)
- アクセシビリティ最適化 (スクリーンリーダー等は MVP 後)
- ストア要件最終調整 / 法務レビュー (ベータ後)
- 多言語対応
- フルレングス楽曲の転送 (短尺サンプルのみ)
- 楽曲送信側の選択 UI (受信体験優先)
- 楽曲のエクスポート / 共有

### 前提となる外部システム
- なし (完全 P2P)
- 将来的にバックエンド (GCP サーバレス) を導入する場合は別 spec で扱う
